01 / 项目简述

在 BitNet 骨干上实现 Kev 式结构化决策，并通过 pip 提供 GGUF 常驻推理。

bit-jev 使用 Transformers/PyTorch 训练 BitNet 骨干与指针头，先做 LoRA 微调，再由 Kev 教师 logits 蒸馏学生，导出 I2_S GGUF 和 float32 指针头。README.md 以“普通电脑，CPU 就能跑 JEV，而且很快！”开头，随即给出 pip install bit-jev -i https://pypi.org/simple --upgrade 与 python -m bit_jev.demo。PyPI 0.13.13 的默认 demo 启动本机 Gradio 页面；首次提交才按需下载约 1.19 GB 文件并加载模型。gguf.py 默认先请求 Hugging Face，连接失败后回退 ModelScope，source="modelscope" 可直接选择国内站点。Windows x64 AVX2 的 CPU 与 Vulkan GPU 请求分别启动 wheel 内两个预编译程序。macOS Intel、macOS Apple Silicon 与 Linux x86_64/ARM64 仅有未实测的 CPU 源码构建路径。theme.py 通过 Gradio 当前主题变量设置概率卡片背景、文字、边框和轨道，显式设置标题、选项和百分比颜色；暗色模式提高概率条亮度。本机与在线页面读取同一份样式。core/bit_jev/web 同时构建本地和 ModelScope 免费 2 vCPU 空间的 Choice、Noul、Score 页面，Choice 与 Score 支持增加或删除项目，范围二至四项；Hugging Face 免费静态 Space 通过 iframe 嵌入该运行域名，因为当前账号创建计算型 Space 返回 402。页面与 Python API 共用 BitJev.infer()，不生成答案 token；公开微软基础模型基准与 bit-jev 检查点 AutoDL 案例继续分开说明。

02 / 项目架构拆解

代码逻辑层与功能需求层

代码逻辑层

  1. 输入规范化core/bit_jev/api.py 校验 state、instructions、Noul、Choice、Score 字段并统一答案结构；encoding.py 在分词前转义用户文本中的控制分隔符。
  2. 问题编码core/bit_jev/encoding.py 把 state、问题、选项和 decide 位置变成 BitNet 预留 token 与正文 token 序列；记录每个选项结束位置及对应问题的决定位置。此模块无需导入 PyTorch。
  3. 分支掩码同文件的 block-causal mask 使问题读取共享 state 与自身分支，阻断跨问题信息；打包 PyTorch 前向可复用一次 state 计算。
  4. 骨干与指针头DecisionModel 取得隐藏状态，PointerHead 对选项与决定位置分别投影、点积、缩放，再把候选分数转成概率。
  5. 训练与评估train.py 管理监督训练；distill.py 读取离线教师分数并更新学生；eval.py 生成逐题结果与准确率、校准统计。输入数据和模型均由操作者自行提供。
  6. 导出协议export_distilled.py 校验本地检查点并转换 I2_S GGUF；cpu_head.py 将 q/k 参数写成原生 float32 文件；manifest.json 记录导出文件摘要。
  7. GGUF 请求路径gguf.py 先判断本地目录，再按 source 参数或 BIT_JEV_MODEL_SOURCE 选择下载站点。auto 模式用 5 秒元数据超时尝试 Hugging Face，失败后映射至 JingHao9616/bit-jev-2b-distilled 并用 modelscope-hub 下载同一组推理文件。随后等待原生加载握手并复用常驻进程；cpu.py 将多题请求拆成多条因果行；native/main.cpp 用选定 CPU/Vulkan/CUDA 后端读取隐藏状态、计算指针头并返回 JSONL 选项分布。
  8. 程序选择gguf.py 在下载模型前调用 native_build.py：先找对应版本的用户缓存，再按设备选择 Windows x64 wheel 内的 CPU EXE 或 Vulkan EXE，检查 AVX2；Vulkan 额外检查系统是否能加载 vulkan-1.dll。只有缺少包内目标、选择 CUDA，或显式指定 native_source= 时才走源码构建；默认源码路径核对 BitNet/llama.cpp 固定提交并应用 ReLU² 补丁。
  9. 零文件网页入口core/bit_jev/demo.py 默认解析 model、source、device、threads、gpu-index、host 与 port，调用 web/app.py 启动本机 127.0.0.1:7860 页面，浏览器提交前不下载权重。--once 保留手写客服请求的命令行一次性推理与 JSON 输出。
  10. 共用表单与结果路径core/bit_jev/web/forms.py 建立 Choice、Noul、Score 三个任务 Tab 和全局中英语言切换；Choice 默认两项、Score 默认三级，均可增加或删除任意项目，后续内容前移，保持二至四项。问题下方的背景与项目旁的说明按钮默认折叠，展开的说明占满表单宽度。logic.py 把折叠 Textbox 的 None 按未填写处理，空背景传入“常见问题”，空说明复制项目内容，校验文本长度、重复项和四项上限。service.py 延迟加载模型并用锁保护常驻原生进程；presentation.py 生成转义后的结论和概率条，原始 JSON 放在高级结果折叠区。ModelScope spaces/bit_jev_demo/app.py 只是调用共用页面工厂；Dockerfile 构建 Linux CPU 程序，Hugging Face 静态入口以 iframe 嵌入该运行域名。

功能需求层

  1. 安装即用用户执行 pip install bit-jev -i https://pypi.org/simple --upgrade 和 python -m bit_jev.demo 即可打开本机页面；首次点击推理才下载约 1.19 GB 模型，之后复用站点缓存。国内网络可指定 --source modelscope 跳过 Hugging Face；指定 --device gpu 改用 Vulkan。
  2. 中英双语本地与在线试用用户在 Choice、Noul、Score 三个 Tab 间切换，再用全局语言开关选择中文或英文。中文 Choice 预填“2027年，如果拿出1000美金，我应该买比特币还是黄金”，选项为“比特币”“黄金”；问题必填，背景与每项说明可选，未展开的 None 与空文本按同一缺省值处理；Choice 与 Score 均允许添加或删除至二至四项，Noul 固定否／是。页面按结论、可读概率条、可折叠原始 JSON 的顺序呈现实际结果与原生计算时间。Logo 随 wheel 打包，不依赖模型站点图片请求；Hugging Face 免费静态页面嵌入 ModelScope 的共用页面。
  3. 结构化输出Choice 返回候选项概率，Noul 返回真假判断，Score 返回有序评分分布；每题只在调用方给出的候选集合内选择。
  4. 题目隔离训练路径用注意力掩码隔离分支；原生路径逐题清理 KV 缓存后执行独立因果行，保证一个问题不能看到另一个问题文本。
  5. 一次读出每条原生因果行以前向计算取得所有候选分数；没有逐个生成答案 token 的循环。多题原生请求仍逐题重算共享 state。
  6. 量化兼容导出器按在线量化对应的三元舍入规则写 I2_S；原生 runner 从 GGUF 取得骨干隐藏状态，从 head.f32 取得指针头参数。
  7. 发行与兼容性Windows x64 AVX2 wheel 内嵌已编译 CPU EXE、Vulkan EXE、原生源码、补丁和 BitNet/llama.cpp 的 MIT 许可文本；其他平台由源码包提供构建输入。Vulkan EXE 需要显卡驱动提供运行时加载器，但普通推理不需要 SDK。公开 GGUF 分别放在 Hugging Face 与 ModelScope，模型卡说明相同的数据来源和权重许可边界；代码许可证不授予检查点的开放权重许可。
  8. 性能研究test/benchmark_public_base.py 核对微软公开 GGUF 的固定大小与 SHA-256，再顺序测 CPU 原生与 Vulkan 混合路径；render_public_base_figures.py 从原始样本生成可公开的速度、内存图和剔除本机路径的 JSON。原 bit-jev 检查点的测量值始终留在本地。
  9. 数据权限训练脚本属于研究实现，不承诺其历史数据配方可用于公开权重分发。任何新训练、教师输出、模型与评估结果都须按各自数据和模型条款审查。

03 / 数据流动层

输入如何走到候选项答案

1 / 输入TypeSafe JSONstate、instructions、questions、候选项；由 api.py 规范化。
2 / 编码encoding.py插入保留分隔符、转义用户控制文本，保存 option-close 与 decide 位置；无需加载 PyTorch。
3 / 训练前向分支掩码 + BitNet共享 state 一次，多个问题分支并行读取各自上下文。
4 / 决策读出PointerHead选项隐藏状态与决定隐藏状态投影、点积、温度缩放、softmax。
5 / 本地导出GGUF + head.f32兼容检查点由 export_distilled.py 和 cpu_head.py 转成原生 CPU 文件；输出留在本机。
6 / pip 加载demo.py → web → gguf.py默认入口先启动本机 Gradio，首次提交后才由 service.py 触发预检查。Windows x64 AVX2 按 CPU/GPU 选 wheel 内 CPU 或 Vulkan EXE，GPU 检查系统 loader。其他平台、CUDA 或指定源码才构建。优先读取本地目录；auto 模式先向 Hugging Face 请求，失败时从 ModelScope 获取 GGUF、头和 tokenizer，最后等待加载握手。--once 跳过页面并执行手写请求。
7 / 原生计算native/main.cppcpu.py 将多题拆成因果行；原生程序逐行清 KV、用选定后端运行 I2_S 骨干、读取隐藏状态并应用指针头。
8 / 输出JSONL → TypeSafe原生程序返回 logits、概率和原生耗时；gguf.py 恢复 Choice、Noul、Score 答案。
本地与在线页面支线三个任务 Tab → BitJev.infer全局语言切换 → forms.py 显示问题、可选背景和二至四项的增加／删除操作 → logic.py 补默认值并构造 Choice／Noul／Score JSON → service.py 的常驻进程 → presentation.py 输出结论、概率条和高级 JSON。本地页面在用户机器运行；ModelScope 2 vCPU 容器运行同一实现，Hugging Face 静态页面通过 iframe 展示其结果。
预编译构建支线固定源码 → CPU 与 Vulkan ReleaseBitNet 0b341e58、llama.cpp 390c3077、ReLU² 补丁。CPU 使用 MSVC 静态运行库；Vulkan 使用 MinGW 静态 GCC 运行库和编入的着色器，只动态加载系统 vulkan-1.dll。两者关闭 GGML_NATIVE/OpenMP，启用 AVX2。

执行边界：GGUF 只装 backbone；原生指针头需独立的 head.f32。公开模型从 Hugging Face 或 ModelScope 按需下载，约 1.19 GB，不进入 PyPI wheel；两个站点的推理文件须与同一份 SHA-256 清单核对。原生路径对每题重算 state；GPU 层卸载由 Vulkan/CUDA 编译后端和可见设备决定，不能把历史 FP16 PyTorch 的 5090 计时当作 GGUF GPU 性能。

05 / 构建与验证

pip 入口、源码构建与真实 GGUF 测试

  1. 安装与示例用户执行 pip install bit-jev -i https://pypi.org/simple --upgrade，再执行 python -m bit_jev.demo，默认在 127.0.0.1:7860 打开浏览器页面。页面创建时不下载模型；首次点击推理才调用 BitJev.from_pretrained()。--once 运行原来的单题命令行示例；--device gpu 选择 Vulkan。默认依赖包含 Gradio、Transformers 与 huggingface_hub；训练依赖通过 bit-jev[train] 安装。安装本身不下载权重、不编译上游库。
  2. 程序预检查BitJev.from_pretrained() 在下载约 1.19 GB 模型前，按已有版本缓存、Windows x64 AVX2 wheel 内设备对应 EXE、源码构建的次序选程序。cpu 选 bit-jev-cpu.exe，gpu/vulkan 选 bit-jev-vulkan.exe 并加载系统 vulkan-1.dll。只有源码路径检查 Git（默认自动获取源码才需要）与 CMake 3.28+；没有 AVX2 或 Vulkan loader 时在下载权重前报明确错误。
  3. 下载与缓存预检查通过后从公开 Hub 仓库只取 GGUF、head、tokenizer 和配置；本地目录可直接传入。缺少文件时在启动原生程序前报错。
  4. 取得与核对依赖源码构建时，native_build.py 在用户缓存下载 BitNet 固定提交 0b341e58 与 llama.cpp 固定提交 390c3077，只应用 ReLU² 运行时补丁。Windows x64 AVX2 预编译 CPU/Vulkan 推理跳过此步骤；源码训练/导出仍使用 test/bootstrap_bitnet.py 取得转换器补丁。
  5. 构建与握手源码路径由 CMake 根据 cpu、vulkan 或 cuda 启用后端；Windows MSVC 对 main.cpp 使用 /utf-8。预编译路径直接启动已打包的程序。C++ 载入 GGUF 和 head 后发送 ready 握手，Python 此时才返回模型对象。GPU 请求无可用设备时报错，不静默退回 CPU。
  6. 真实请求test/test_pypi_inference.py 从隔离安装的 wheel 自动取得包内 Vulkan EXE，将 PATH 限定为 Windows 系统目录并模拟 Git/CMake 不可见，在 RTX 2060 上加载公开 GGUF；同一模型进程对手写客服请求调用两次 infer，核对 Choice、Noul、Score 答案一致。该测试只验证无需 SDK 的安装与运行，不形成跨机器速度结论。

CPU EXE 沿用 MSVC 19.43 AVX2 Release；Vulkan EXE 来自固定 BitNet 0b341e58 / llama.cpp 390c3077 且仅含 ReLU² 补丁的 MinGW Release，大小 45,801,472 字节，SHA-256 为 CF2BB4815DE2CABC6C88B790B55A4A39B6D270CEEC3E791E4F634B211B74E516。MinGW 编译器运行库静态链接；dumpbin 仅列 Windows 系统/UCRT DLL 和 vulkan-1.dll。上一版 0.12.10 wheel 为 16,391,036 字节，源码包为 16,136,359 字节，曾通过归档检查、twine check 与两次真实 CPU 推理。0.13.10 首次加入本地网页，随后 0.13.11 修正 GPU 耗时标签；0.13.11 wheel 为 17,750,457 字节，源码包为 17,491,878 字节，归档检查与 twine check 均通过。ModelScope 远端推理文件经 SDK 按需获取并返回正确目录；CUDA 后端与其他平台仍未在对应机器实测。

06 / 公开基础模型测量

同一微软 I2_S GGUF 的两条部署路径

输入来源固定为 microsoft/bitnet-b1.58-2B-4T-gguf 修订 9f43072f69492cbd5bc5d5ebb085fec519686a93，GGUF 大小 1,844,472,032 字节，SHA-256 以 benchmark_public_base.py 的常量核对。先执行 bootstrap_bitnet.py 应用转换器与 ReLU² 补丁，再给固定 llama.cpp 应用 public-bitnet25-compat.patch；CPU-only 与 Vulkan 版本分别构建到 test/build-public-base 和 test/build-public-vulkan。Vulkan1 指向 RTX 2060；Vulkan0 是集成显卡，不能自动选择。

测量程序对 128 输入 token 的预填充和 32 输出 token 的解码分别预热并各重复五次，依次启动两个二进制；吞吐排除模型加载。CPU 原生路径中位吞吐为 56.23 / 4.57 token/s，Vulkan 混合路径为 45.20 / 3.56 token/s。进程 RSS 在加载与测试期间采样，峰值分别为 1,230.19 / 1,955.56 MiB。显存仅有 nvidia-smi 整卡基线增量：CPU 0 MiB、Vulkan 722 MiB；不能当成每进程模型显存。GPU 虽配置卸载 31/31 层，仍有 1,124.80 MiB 模型缓冲区映射在 CPU。以上数据属于公开基础语言模型合成基准，不是 bit-jev 判题或 Kev 对照。

详细方法与复现命令见 docs/BENCHMARKS.zh-CN.md；逐次样本见 docs/benchmark-data/public-bitnet-base-2026-09-27.json。本组结果不得替代 bit-jev 检查点的每请求延迟与准确率验证。
