01 / 项目简述

在 BitNet 骨干上实现 Kev 式结构化决策，并提供原生 CPU 推理源码。

bit-jev 用 Python、PyTorch、Transformers 编码多题决策请求；block-causal 注意力隔离题目分支，指针头对给定选项评分；兼容检查点可导出 I2_S GGUF 和 float32 指针头，由 C++ 原生程序在 CPU 上逐题完成分类。本次公开发布包含源码、许可、架构文档、构建脚本，以及微软公开 BitNet 基础模型的独立测量图和逐次样本；历史 bit-jev 训练权重、模型包及其衍生结果仍不公开。

02 / 项目架构拆解

代码逻辑层与功能需求层

代码逻辑层

  1. 输入规范化core/bit_jev/api.py 校验 state、instructions、Noul、Choice、Score 字段，统一答案输出结构；用户文本在 model.py 编码前处理控制分隔符。
  2. 问题编码core/bit_jev/model.py 把 state、问题、选项和 decide 位置变成 BitNet 预留 token 与正文 token 序列；记录每个选项结束位置及对应问题的决定位置。
  3. 分支掩码同文件的 block-causal mask 使问题读取共享 state 与自身分支，阻断跨问题信息；打包 PyTorch 前向可复用一次 state 计算。
  4. 骨干与指针头DecisionModel 取得隐藏状态，PointerHead 对选项与决定位置分别投影、点积、缩放，再把候选分数转成概率。
  5. 训练与评估train.py 管理监督训练；distill.py 读取离线教师分数并更新学生；eval.py 生成逐题结果与准确率、校准统计。输入数据和模型均由操作者自行提供。
  6. 导出协议export_distilled.py 校验本地检查点并转换 I2_S GGUF；cpu_head.py 将 q/k 参数写成原生 float32 文件；manifest.json 记录导出文件摘要。
  7. CPU 请求路径cpu.py 将多题请求拆成多条“共享 state + 单题分支”因果行；native/main.cpp 常驻加载 GGUF 和指针头、读取隐藏状态、返回 JSONL 选项分布；Python 恢复 TypeSafe 答案。
  8. 依赖构建test/bootstrap_bitnet.py 核对固定 BitNet 与 llama.cpp 提交、浅拉取子模块并应用两份补丁；core/native/CMakeLists.txt 构建 CPU 可执行文件。

功能需求层

  1. 结构化输出Choice 返回候选项概率，Noul 返回真假判断，Score 返回有序评分分布；每题只在调用方给出的候选集合内选择。
  2. 题目隔离训练路径用注意力掩码隔离分支；原生路径逐题清理 KV 缓存后执行独立因果行，保证一个问题不能看到另一个问题文本。
  3. 一次读出每条原生因果行以前向计算取得所有候选分数；没有逐个生成答案 token 的循环。多题原生请求仍逐题重算共享 state。
  4. 量化兼容导出器按在线量化对应的三元舍入规则写 I2_S；原生 runner 从 GGUF 取得骨干隐藏状态，从 head.f32 取得指针头参数。
  5. 可复现源码仓库固定上游提交和补丁，允许在独立机器上检查依赖源码、构建可执行文件及运行命令帮助；真实分类需要额外提供合法取得的兼容检查点。
  6. 性能研究test/benchmark_public_base.py 核对微软公开 GGUF 的固定大小与 SHA-256，再顺序测 CPU 原生与 Vulkan 混合路径；render_public_base_figures.py 从原始样本生成可公开的速度、内存图和剔除本机路径的 JSON。原 bit-jev 检查点的测量值始终留在本地。
  7. 数据权限训练脚本属于研究实现，不承诺其历史数据配方可用于公开权重分发。任何新训练、教师输出、模型与评估结果都须按各自数据和模型条款审查。

03 / 数据流动层

输入如何走到候选项答案

1 / 输入TypeSafe JSONstate、instructions、questions、候选项；由 api.py 规范化。
2 / 编码model.py插入保留分隔符、转义用户控制文本，保存 option-close 与 decide 位置。
3 / 训练前向分支掩码 + BitNet共享 state 一次，多个问题分支并行读取各自上下文。
4 / 决策读出PointerHead选项隐藏状态与决定隐藏状态投影、点积、温度缩放、softmax。
5 / 本地导出GGUF + head.f32兼容检查点由 export_distilled.py 和 cpu_head.py 转成原生 CPU 文件；输出留在本机。
6 / CPU 编码cpu.py把一个多题请求拆成每题一条因果行，保留共享 state 的文字内容。
7 / 原生计算native/main.cpp逐行清 KV、运行 I2_S 骨干、读取指定隐藏状态、应用指针头。
8 / 输出JSONL → TypeSafe原生程序返回 logits 和概率；cpu.py 恢复 Choice、Noul、Score 答案。
源码验证支线bootstrap → CMake固定上游 Git 提交、应用补丁、构建原生程序、检查命令帮助；无需训练权重。

执行边界：GGUF 只装 backbone；原生指针头需独立的 head.f32。纯源码克隆可以验证编译和接口，无法直接产生真实分类答案。若请求包含多个问题，当前原生路径逐题重算 state；这与打包 PyTorch 前向的一次共享 state 路径不同。

05 / 构建与验证

源码克隆后可独立检查的步骤

  1. 安装包在项目根目录执行 python -m pip install -e ./core，确认 Python 包元数据和模块入口可加载。
  2. 取得依赖执行 python test/bootstrap_bitnet.py；脚本取得固定 BitNet 提交，浅拉取其 llama.cpp 子模块，应用仓库内转换器与 ReLU² 补丁。
  3. 核对补丁执行 python test/bootstrap_bitnet.py --check，比对两个 Git 提交和补丁状态；该步骤不需要训练权重。
  4. 构建原生程序通过 cmake -S core/native -B core/build/bit-jev-cpu 配置，再用 cmake --build core/build/bit-jev-cpu --target bit-jev-cpu 编译；具体生成器和编译器按平台选择。
  5. 检查命令执行 python -m bit_jev.cpu --help 查看 JSONL 推理参数。要产生答案，还需自行提供有权使用的兼容 run、GGUF、head 与 tokenizer。

独立临时工作区曾从本机 Git 镜像完成固定提交核对、补丁应用和原生编译；直接从公共 GitHub 拉取 llama.cpp 子模块的网络传输没有完成，因此公开网络首次克隆仍需另行验证。这是源码构建链路的验证边界。

06 / 公开基础模型测量

同一微软 I2_S GGUF 的两条部署路径

输入来源固定为 microsoft/bitnet-b1.58-2B-4T-gguf 修订 9f43072f69492cbd5bc5d5ebb085fec519686a93，GGUF 大小 1,844,472,032 字节，SHA-256 以 benchmark_public_base.py 的常量核对。先执行 bootstrap_bitnet.py 应用转换器与 ReLU² 补丁，再给固定 llama.cpp 应用 public-bitnet25-compat.patch；CPU-only 与 Vulkan 版本分别构建到 test/build-public-base 和 test/build-public-vulkan。Vulkan1 指向 RTX 2060；Vulkan0 是集成显卡，不能自动选择。

测量程序对 128 输入 token 的预填充和 32 输出 token 的解码分别预热并各重复五次，依次启动两个二进制；吞吐排除模型加载。CPU 原生路径中位吞吐为 56.23 / 4.57 token/s，Vulkan 混合路径为 45.20 / 3.56 token/s。进程 RSS 在加载与测试期间采样，峰值分别为 1,230.19 / 1,955.56 MiB。显存仅有 nvidia-smi 整卡基线增量：CPU 0 MiB、Vulkan 722 MiB；不能当成每进程模型显存。GPU 虽配置卸载 31/31 层，仍有 1,124.80 MiB 模型缓冲区映射在 CPU。以上数据属于公开基础语言模型合成基准，不是 bit-jev 判题或 Kev 对照。

详细方法与复现命令见 docs/BENCHMARKS.zh-CN.md；逐次样本见 docs/benchmark-data/public-bitnet-base-2026-09-27.json。本组结果不得替代 bit-jev 检查点的每请求延迟与准确率验证。
